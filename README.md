# AI-бот (Telegram) — Claude Opus 5 / GPT-5.6 Luna / Sol / Terra / Gemini (image)

Полностью переписанный бот под твои требования: баланс + оплата через Platega,
6 моделей с продажей пакетов токенов/генераций (наценка +30% к цене ProxyAPI), админ-панель,
тикеты поддержки, рефералка, работа через ProxyAPI. Текстовые модели понимают фото и файлы
(PDF, txt/json/csv и т.п.), присланные прямо в чате.

Технологии: **aiogram 3** (Telegram), **SQLite** (через aiosqlite, отдельный файл `bot.db`,
не требует поднимать Mongo/Postgres), **aiohttp** (приём вебхука от Platega), **httpx** (запросы к ProxyAPI).

## 1. Установка

```bash
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

Заполни `.env`:

| Переменная | Что это |
|---|---|
| `BOT_TOKEN` | токен бота от @BotFather |
| `ADMIN_IDS` | твой Telegram ID (и других админов через запятую) |
| `CHANNEL_URL` | ссылка на твой канал (кнопка "Наш канал") |
| `PROXYAPI_KEY` | секретный ключ ProxyAPI. Можно оставить пустым и ввести позже прямо в боте: Админ-панель → ⚙️ Настройки ProxyAPI |
| `PLATEGA_MERCHANT_ID`, `PLATEGA_SECRET` | данные из личного кабинета Platega |
| `PUBLIC_BASE_URL` | публичный домен твоего сервера, на который смотрит вебхук Platega |

Свой Telegram ID можно узнать у @userinfobot.

Запуск:

```bash
python3 bot.py
```

Бот поднимет:
- Telegram-поллинг (сам бот);
- aiohttp-сервер на порту `WEBHOOK_PORT` (по умолчанию 8080) с эндпоинтом `PLATEGA_WEBHOOK_PATH` (по умолчанию `/platega-webhook`) — сюда должен стучаться Platega.

В личном кабинете Platega укажи вебхук:
`https://<твой_домен>/platega-webhook`
(проксируй его через nginx/Caddy на порт 8080, как любой другой веб-сервис).

## 2. Как устроена монетизация

### 2.1. Пополнение баланса (п.1 ТЗ)

Пользователь жмёт "💰 Баланс" → "➕ Пополнить баланс" → вводит **любую сумму от 100 ₽**
(порог задаётся в `.env`: `MIN_TOPUP_RUB`) → бот создаёт платёж в Platega и присылает ссылку.
После оплаты Platega стучится на вебхук, бот зачисляет деньги на баланс автоматически
и присылает уведомление пользователю. Всё идемпотентно — двойное зачисление по одному
платежу исключено (см. `webhook.py`, таблица `settings` хранит флаг `tx_credited:<id>`).

Быстрые кнопки сумм (100/300/500/1000/3000/5000 ₽) — просто быстрый выбор,
плюс всегда доступен ручной ввод произвольной суммы.

### 2.2. Покупка моделей пакетами токенов (п.1 ТЗ)

Ровно 3 модели, как просил:

| Модель | Тип | Провайдер |
|---|---|---|
| Claude Opus 5 | текст | Anthropic |
| GPT-5.6 Luna | текст | OpenAI |
| Gemini 3.1 Flash Lite (image) | генерация изображений | Google |

Пакеты — как ты и просил: **10к / 50к / 100к / 200к / 500к** (для текстовых моделей — токены,
для картиночной — генерации в той же пропорции: 5 / 25 / 50 / 100 / 250 изображений,
так как продавать "токены" для картинок неудобно пользователю — там понятнее считать штуками).

**Наценка +30% зашита в формулу**, а не захардкожена цифрами:

```
цена_продажи = себестоимость × 1.3   (MARKUP в pricing.py)
```

Себестоимость взята из твоего скриншота прайса (₽ за 1М токенов, среднее ввод/вывод).
Всё лежит в `pricing.py` — если у тебя изменится закупочная цена в ProxyAPI,
меняешь только числа `cost_rub_per_1m` / `cost_rub_per_generation`, всё остальное
пересчитается сама (пакеты, карточки, кнопки).

Купленные токены хранятся **раздельно по каждой модели** (таблица `wallets`) —
это честно и прозрачно для пользователя: купил под Claude — тратится только на Claude.

### 2.3. Реферальная система (п.6 ТЗ)

За каждого приглашённого (переход по ссылке `t.me/bot?start=ref<ID>`) рефереру начисляется:

- **7 бесплатных запросов к GPT-5.6 Luna** сразу после регистрации друга (тратятся
  автоматически, когда у пользователя закончились купленные токены Luna — сначала
  списываются они, а не деньги; на другие модели бесплатные запросы не действуют);
- **5% от каждой покупки модели** приглашённым — начисляется сразу на баланс реферера
  (без ограничения по сумме и сроку), с уведомлением в личку.

Оба параметра настраиваются в `.env` (`REFERRAL_FREE_REQUESTS`, `REFERRAL_COMMISSION_PERCENT`).

Плюс **каждый новый пользователь** (независимо от того, пришёл он по рефералке или нет)
получает приветственный бонус — **5000 токенов GPT-5.6 Luna**
(`SIGNUP_BONUS_LUNA_TOKENS` в `.env`, можно поставить 0, чтобы отключить).

### 2.4. Промокоды

Админ создаёт промокод в формате `КОД СУММА КОЛ_ВО_АКТИВАЦИЙ` (например `SALE2026 200 100` —
200 ₽ бонуса, максимум 100 активаций). Пользователь вводит код в разделе "🎁 Промокод",
бонус зачисляется на баланс. Повторная активация одним и тем же пользователем невозможна.

## 3. Админ-панель (п.2 ТЗ)

Доступна двумя способами: командой `/admin` или кнопкой "🛠 Админ-панель" в главном меню
(кнопка видна только тем, чей ID есть в `ADMIN_IDS`).

Функции (как на твоём скриншоте, без "Подписка выдать/забрать" — как ты и просил убрать):

- 💸 **Выдать баланс** — по ID пользователя начисляет рубли на баланс.
- 🔍 **Найти пользователя (ID)** — по ID или @username показывает баланс, бесплатные запросы, бан-статус.
- ✉️ **Написать одному (ID)** — личное сообщение конкретному пользователю от бота.
- 📣 **Рассылка всем** — сообщение всем пользователям базы (с небольшой задержкой между отправками,
  чтобы не упереться в лимиты Telegram).
- 🎫 **Тикеты** — список открытых обращений, ответ прямо из бота, закрытие тикета.
- 👥 **Пользователи** — общее число.
- 🧾 **История платежей** — последние транзакции всех пользователей.
- 🎁 **Промокоды** — создание новых промокодов.
- 📊 **Статистика** — пользователи, открытые тикеты, сумма и число оплаченных платежей.
- ⚙️ **Настройки ProxyAPI** — ввод/смена секретного ключа прямо из бота, без правки `.env`
  и без перезапуска (п.4 ТЗ — "просто ввёл ключ и всё работает").

## 4. Тикеты поддержки (п.3 ТЗ)

Раздел "🛟 Поддержка" содержит:
- пользовательское соглашение (ссылка из `.env`, если задана);
- политику конфиденциальности (ссылка из `.env`, если задана);
- создание тикета (пользователь пишет сообщение → админам приходит уведомление

- переписку внутри тикета в обе стороны (пользователь ↔ админ), закрытие тикета админом.

## 5. ProxyAPI (п.4 ТЗ) — сделано именно под proxyapi.ru

Ключ вводится **один раз** — либо в `.env` (`PROXYAPI_KEY`), либо прямо в боте
(Админ-панель → Настройки ProxyAPI, хранится в базе и имеет приоритет над `.env`).

Важный нюанс: ProxyAPI **специально не унифицирует** протоколы — у каждого провайдера
сохраняется его родной формат запроса/ответа, чтобы можно было пользоваться официальной
документацией и библиотеками. Поэтому бот стучится в 3 разных эндпоинта в зависимости
от провайдера модели (`proxyapi_client.py`):

| Модель | Провайдер | Эндпоинт ProxyAPI | Формат |
|---|---|---|---|
| GPT-5.6 Luna | openai | `POST /openai/v1/chat/completions` | OpenAI Chat Completions |
| Claude Opus 5 | anthropic | `POST /anthropic/v1/messages` (+ заголовок `Anthropic-Version`) | Anthropic Messages API |
| Gemini 3.1 Flash Lite (image) | google | `POST /google/v1beta/models/{model}:generateContent` с `generationConfig.responseModalities: ["IMAGE"]` | нативный Gemini generateContent, картинка приходит как base64 в `inlineData` |

Всё это уже реализовано и протестировано на синтаксис/логику. Единственное, что нужно
проверить у себя в личном кабинете ProxyAPI перед запуском — что модели с именами
`gpt-5.6-sol`, `claude-opus-5`, `gemini-3.1-flash-lite` доступны на твоём тарифе
именно под такими ID (это имена с твоего скриншота прайса ProxyAPI — если в кабинете
они называются иначе, поменяй `proxyapi_model` в `pricing.py`, менять больше ничего
не нужно).

⚠️ Важно про Platega: точные названия заголовков авторизации и формат подписи вебхука
могут отличаться в зависимости от того, что тебе выдаст менеджер Platega при подключении —
их подробная техническая вики закрыта от автоматического индексирования. В `platega.py`
реализована стандартная для их API схема (`POST /transaction/process`, заголовки
`X-MerchantId` / `X-Secret`, подпись вебхука HMAC-SHA256). Если менеджер Platega пришлёт
другие названия заголовков — поменяй константы `HEADER_MERCHANT` / `HEADER_SECRET` /
`SIGNATURE_HEADER` в начале файла (можно и через переменные окружения `PLATEGA_HEADER_MERCHANT`
и т.п. — они уже подключены).

## 6. Главное меню (п.5 ТЗ)

Главное меню теперь закреплено внизу экрана (Telegram reply-keyboard), а не в виде
инлайн-кнопок под сообщением — так оно всегда под рукой, независимо от того, что
показано в чате выше.

- 💬 Начать чат — только выбор модели → карточка модели → «Начать диалог». Пакеты токенов
  здесь не показываются: это чистый путь «выбрал модель — начал общаться» на уже имеющемся
  балансе токенов, без соблазна/лишнего шага купить что-то по пути.
- 🛒 Покупка — та же карточка модели, но уже с пакетами токенов на покупку.
- 👤 Профиль — ID, баланс, бесплатные запросы, остаток токенов по каждой модели.
- 💰 Баланс — пополнение (минимум {min_topup} ₽) и история платежей.
- 🎁 Промокод.
- 🛟 Поддержка — соглашение, политика конфиденциальности, тикеты.
- 👥 Рефералы — реферальная ссылка, счётчик приглашённых, условия бонусов.
- 📢 Наш канал.
- 🛠 Админ-панель (только для админов).

Во время диалога с моделью снизу экрана — отдельная пара кнопок:
🧹 Очистить диалог / ⬅️ В главное меню (тоже закреплены внизу, а не под сообщением).
Диалог можно чистить и командой `/new_chat`.

## 6.1. Голосовые сообщения — бесплатное распознавание речи

Во время диалога с любой моделью можно присылать не только текст, фото и файлы, но и
**голосовые сообщения** (и обычные аудиофайлы). Бот распознаёт речь локально через
faster-whisper (открытая модель Whisper) — **без сторонних платных API**: единственные
расходы — вычислительные ресурсы твоего сервера. Распознанный текст обрабатывается точно
так же, как если бы пользователь напечатал его сам (включая генерацию картинок голосом —
надиктовал описание, получил изображение).

Настройки — в `.env`:
```
WHISPER_MODEL_SIZE=small     # tiny/base/small/medium/large-v3 — точность vs скорость/память
WHISPER_DEVICE=cpu           # cpu или cuda (если на сервере есть GPU)
WHISPER_COMPUTE_TYPE=int8    # int8 для CPU, float16 для GPU
```
При первом голосовом сообщении модель скачается с Hugging Face (один раз, нужен интернет
на сервере) и дальше будет держаться в памяти. Если на сервере мало RAM — ставь `tiny` или
`base`; если он совсем слабый по CPU — распознавание первых сообщений может занимать
несколько секунд, это нормально.

## 7. Фишки от себя (п.7 ТЗ)

- **🧹 Очистить чат** — прямо во время диалога с нейросетью можно обнулить историю сообщений
  одной кнопкой (или командой `/new_chat`), чтобы не тратить токены на разросшийся контекст.
- **Краткое описание модели прямо в карточке покупки** — что это за модель и для каких задач
  подходит, до того как пользователь платит.
- **Раздельные кошельки токенов по моделям** — прозрачно видно, на что именно потрачены деньги.
- **Бесплатное распознавание голосовых** — см. раздел 6.1 выше.
- **Идемпотентная обработка вебхуков** — повторная доставка от Platega не задвоит зачисление.
- **Ключ ProxyAPI меняется на лету** из бота, без деплоя.

Дальше можно докрутить (не делал по умолчанию, чтобы не раздувать бота лишним, но легко добавить):
- автоматическое напоминание, если баланс токенов подходит к нулю;
- ежедневный лимит бесплатных запросов вместо разового пула;
- экспорт истории диалога в файл;
- уведомление админам о новых пополнениях в реальном времени.

## 8. Структура проекта

```
config.py           — все настройки из .env
database/
  db.py              — SQLite: пользователи, кошельки, транзакции, тикеты, промокоды
pricing.py           — 6 моделей, формула наценки +30%, пакеты токенов (текст и картинки — всё в токенах)
proxyapi_client.py   — запросы к ProxyAPI (чат + генерация картинок)
voice.py             — бесплатное локальное распознавание голосовых (faster-whisper)
platega.py           — создание платежа + проверка подписи вебхука
keyboards.py         — клавиатуры (нижнее reply-меню + inline-подменю)
texts.py             — все тексты интерфейса (правь смело)
webhook.py           — aiohttp-сервер, принимающий колбэк от Platega
bot.py               — точка входа: поднимает бота и вебхук-сервер вместе
handlers/
  user.py            — профиль, баланс, покупки, промокоды, тикеты, рефералка, чат с моделями
  admin.py           — вся админ-панель
requirements.txt
.env.example
```

Запуск: `python bot.py` (из корня проекта — рядом с `config.py`).

Готово к запуску. Если что-то нужно докрутить под себя — структура специально сделана плоской
и без магии, чтобы было легко редактировать самому.
